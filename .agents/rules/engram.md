# Engram Rule

Always follow `.agents/AGENTS.md` and `Protocols/Engram-Protocol.md`.

Load context progressively: `CONTEXT-MAP.md` routes, `Engram/INDEX.md` catalogs, and relevant pages provide substance. Do not broadly scan by default.

Keep append-only raw evidence separate from the editable derived wiki. Never rewrite a Raw Capture, raw source artifact or locator manifest, dated raw health evidence, or an existing `Engram/LOG.md` entry. Never modify a raw source manifest after creation to add a backlink. Reciprocal backlinks belong only between editable derived pages.

Determine authority by claim type, provenance, date, and scope. Do not apply one global source hierarchy to user preferences, decisions, external facts, health records, and interpretations.

Prefer standard Markdown links with resolvable relative paths. Create a page only for a standalone entity or concept; otherwise update the canonical page.

Keep `Engram/INDEX.md` a complete catalog of navigable corpus pages, including sessions and raw manifests; keep `CONTEXT-MAP.md` small. `Engram/LOG.md` entries may contain only date, operation, a short non-sensitive title, workspace-relative affected paths, and an optional bounded non-sensitive note—never raw payloads or external absolute paths.

Capture may write raw content immediately. An explicit Explore request authorizes only creation and updates of its temporary non-authoritative session note; it does not approve durable semantic promotion. Safe index, constrained log, derived-page backlink, metadata, and lint-report maintenance may run without separate material approval when meaning does not change. Semantic edits, merge, archive, delete, context changes, project changes, and health interpretation require a proposal and approval.

Use knowledge-impact thresholds:

* low: do not mention saving;
* medium: mention Capture once at a natural boundary;
* high: propose Sync at a natural boundary.

Never create hidden Git commits. Checkpoints require a current user request or explicit approval and are never automatic after Capture or Query.

Default to English. Use another conversation language only when requested or configured by the active profile. Keep product and system files in English; preserve raw user material in the language received.
